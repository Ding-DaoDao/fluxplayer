# 在线听书磁盘缓存

在线听书的数据源已接入 Media3 CacheDataSource，默认开启，默认上限为 2 GB。播放器读取网络音频时会同时写入应用私有目录 `files/listening_stream_cache`，后续请求优先读取已缓存的数据范围，应用重启后仍可使用。

## 设置

在“设置 → 听书”的缓存设置区域，在线播放缓存可单独开启、关闭、清除和调整容量：512 MB、1 GB、2 GB、5 GB、10 GB、20 GB、50 GB、不限。容量不会预先占用。

容量调整立即生效，降低上限会淘汰较久未使用的缓存。调整容量与清理缓存均保留同一缓存实例，不释放正在播放的数据源。清理时仍在写入的内容可能随后重新出现，后续播放也会继续产生缓存。开关从下一次数据源打开时生效，不中断当前请求。

封面缓存仍独立设置，支持 256 MB、512 MB、1 GB、2 GB、4 GB，默认 1 GB。封面容量在下次启动应用时生效。手动下载的离线音频继续使用原有独立容量和清理入口，不受在线播放缓存的淘汰与清理影响。

## 请求与缓存范围

- 缓存只处理 HTTP/HTTPS 的 GET 请求。本地文件及手动下载的音频直接读取，不再重复缓存。
- `.m3u8`、`.mpd` 清单重新从网络获取；普通音频和分片按各自完整资源地址分别缓存。缓存未命中时继续获取书源提供的请求头。
- 缓存键包含书籍、章节和完整资源地址，并进行 SHA-256 摘要，避免不同章节、分片和带不同参数的资源混用。书源更新签名地址后，可能重新缓存该资源，不删除鉴权参数来强行复用缓存。
- 播放器请求的音频范围会写入磁盘，并非自动下载整本书。未播放、未缓冲的部分仍需要网络；播放前仍需要书源解析地址。需要完整离线保存时使用下载功能。
- 缓存初始化或缓存打开失败时回退到网络播放；读取中出现缓存异常时，播放器后续重试绕过故障缓存。

## 验证

仅执行改动文件的 Kotlin 格式检查及 `:feature:tingshu:compileDebugKotlin` 模块编译。不运行测试，不生成或安装 APK；实际播放、容量淘汰和清理效果由用户在设备上验证。
