# 网盘 Provider 功能补充对照

本次对照范围为本地 `wenxi/lib/data/providers/` 中的 123、阿里、夸克、UC、移动和天翼，以及 FluxPlayer 的 `core:data`、`feature:videopicker` 和播放链接解析流程。

## 已有能力

FluxPlayer 已有六家网盘的个人目录浏览、播放、下载、新建文件夹、移动、重命名和删除。阿里已有资源盘、备份盘切换；123 和天翼已有分享浏览与转存，因此继续复用对应客户端。

## 界面入口

- 登录后的网盘目录菜单直接提供 **上传文件、创建分享、打开分享链接**；相册/家庭空间、账号容量、播放设置按网盘能力分别显示。移除原先把所有功能塞在同一弹窗的入口，并合并 123、天翼菜单中的重复分享入口。
- 文件选择、分享浏览、相册和家庭空间采用独立浏览页，固定顶部导航和底部主操作；文件的播放、下载放在行内更多菜单。
- 创建分享分为选文件、设置有效期和提取码、复制结果三个步骤；播放偏好和 UC TV 授权放在单独的播放设置中。
- 登录页：**浏览分享链接**，允许先浏览分享；账号写入操作在登录后启用。
- 上传调用系统文件选择器，支持多选，显示进度，可停止。文件暂存在应用缓存，结束或取消后清理。
- 创建分享支持勾选当前目录中的文件和文件夹、选择有效期、设置提取码、复制结果。天翼和移动的提取码由服务器生成。
- 分享支持进入子目录、返回、勾选转存、选择目标目录，以及明确标注的“转存并播放 / 转存并下载”。不提供绕过转存的直链播放（wenxi 同样走登录后转存取址），避免出现没有源码依据的入口。
- 相册和家庭空间使用可重新取址的网盘 URI，播放记录不只保存短期下载链接。
- UC 的 TV 授权使用 Extscreen 交换令牌；界面说明这一依赖，用户扫码后才启用，可撤销。

## 实现边界和验证

新增界面复用 FluxPlayer 的登录态与文件客户端，不迁移 wenxi 的 Flutter 页面、下载引擎、独立任务中心或全应用账号管理架构。

“转存并播放”会将文件保留在用户选定的目录。它不会创建隐蔽临时目录，也不会在播放后删除转存文件。转存后取址会核对文件 ID、服务端元数据及实际内容长度；不满足原文件要求（例如试看内容或同名旧文件）时提示失败，不会静默播放错误文件。

单元测试使用拦截器返回固定响应，不访问真实网盘或改动云端文件，覆盖请求参数、分享任务失败、分享分页、UTC 有效期、大文件 ID、秒传摘要、分段读取和独立签名向量。Android 界面测试同样使用固定响应。

构建和固定响应测试不能代替六家服务的真实账号联调。会员权限、分享风控、短信或扫码、家庭成员权限，以及服务端接口变更仍需使用对应账号确认；没有把这些服务的在线状态记为已验证。

本次验证结果：数据模块 70 项单元测试通过（含 `ProviderParityRegressionTest` 13 项操作级回归）；Android 界面测试源码编译通过；独立包名的 `assembleUiPreview` 构建通过。两项设备界面测试因手机拒绝安装测试包（`INSTALL_FAILED_USER_RESTRICTED`）未能启动，不能记为通过。源码格式检查保留了原有页面中的通配符导入，其余本次新增和修改的 Kotlin 源码已检查。

补记：天翼分享的 `shareId` 在真实响应中可能是数字，原先用 `getString` 读取会直接抛 `JSONException`；已改为字符串化读取（与 wenxi 的 `str()` 行为一致），对应回归用例 `tianyiProtectedShareValidatesAccessCodeBeforeBrowsing` 通过。

界面验证（2026-10-23 复跑）：在项目内的隔离 Android 35 模拟器（`build/cloud-ui-emulator`，x86_64）上运行 `:feature:videopicker:connectedDebugAndroidTest`，8 项固定响应界面测试全部通过（`CloudFeaturesDialogTest` 4 项 + `CloudBrowserPaginationTest` 4 项）。覆盖分步创建分享、未登录分享输入、独立播放设置、分享文件夹进入与返回、更多菜单、转存目录切换和列表分页。已检查模拟器导出的浅色分享选择/分享表单，以及深色分享浏览/转存目录截图，未见截断或错位。测试未访问真实网盘，也未在用户手机上重新尝试安装。

### 未修（按 wenxi 对齐原则，剩下的属于功能移植规模或产品取舍）

对齐原则：wenxi 能跑通的实现就是基准，不确定的地方直接照抄它的参数与判定，不再以「需要抓包确认」为由搁置。下列条目都是照 wenxi 能改的，只是改动规模更大或牵涉产品取舍：

1. **夸克/UC 分享直链下载（游客免转存）**：wenxi 有完整双通道（游客隔离 cookie + 账号直连 + 401/403/14001 状态分类 + 域名白名单 + 落盘前长度校验）。属于新增能力，与「转存并播放会把文件留在用户目录」的既有边界并存，需要你确认是否要。
2. **UC 网页播放/下载的内容一致性校验**：wenxi 用 md5 + 长度探针拦「会员提示片」。要在列表里保留 md5，并在取址后加探针请求，改动面较大。
3. **转存临时目录 + 自动清理**：wenxi 每次转存建独立临时目录并登记 cleanup。当前刻意改成「留在用户选择的目录」，两者不能同时成立，需要产品取舍。
4. **列表限流 / 429 指数退避**：wenxi 对 list 类请求有节流 + 退避。可以照抄，属于健壮性增强。
5. **天翼 `webFeatureRequest` 失败后重登重试**（签名通道已有重试，网页通道没有）；移动整条链路的「需重新登录」识别。可以照抄 wenxi 的 `_renew` 流程。
6. **移动家庭云 `familyRootPath` 一致性校验**：wenxi 的 `_checkFamilyPath` 会校验「当前目录 path 与 parent 一致」，防止跨目录错位取到别的文件。可以照抄。
7. **阿里分享转存端点**：wenxi 走 `/adrive/v4/batch` + `share_id`，FluxPlayer 走 `/v2/file/copy`。若阿里侧行为不一致，需要改成 wenxi 的 batch 形式。
8. **123/夸克列表的限流节流与分页退避**（与第 4 条同类）。

### 夸克 / UC 彻底分离（2026-10-23）

两家协议同源，但**共享可变状态**导致过「授权 UC TV 后夸克播放失败」。现在按来源拆干净，
代码仍共用一份协议实现（复制两份会各自漂移），但**没有任何共享的可变状态**：

| 状态 | 拆分前 | 拆分后 |
| --- | --- | --- |
| 客户端来源 | `QuarkApiClient.driveType` 可变字段 + `setDriveType()` | 构造参数 `provider`，**不可变**；`setDriveType` 只在来源变化时重建实例 |
| 播放鉴权 | 单例 `object QuarkAuthProvider` | `QuarkPlaybackAuth` 两个实例：`QuarkAuthProvider` / `UcAuthProvider`，按 `quarkPlaybackAuth(provider)` 取 |
| 播放域名头 | `.quark.cn` 单个全局槽 | 注册带来源（`registerFor` / `registerSuffixFor`），查找优先当前来源 → 公共规则 → 其它来源兜底 |
| 匿名域名 | 无来源，永久生效 | `registerAnonymous(host, provider)`，只在来源匹配时生效 |
| 浏览页/下载的头 | 请求时回读全局 | 本次账号的头快照 / 客户端自己的头 |
| 登出 | 清全局（会把另一家也清掉） | 只清本来源 |

回归用例：`quarkAndUcPlaybackAuthAreIndependent`、`providerScopedSuffixHeadersDoNotOverwriteEachOther`、
`ucTvAnonymousHostDoesNotBlockQuarkPlaybackOnSameHost`。

### 已知架构差异（不算缺陷）
